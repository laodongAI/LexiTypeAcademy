## 🔴 严重问题 (Critical Issues)

### Issue #1: AI功能不可用 - 配置流程断裂

**问题描述**:
用户旅程:
```
1. 用户听说AI功能很强大，打开"AI Lab"菜单
2. 看到页面顶部红色警告: "⚠️ AI 服务未配置"
3. 展开"如何配置"，看到:
   "请在设置中配置 AI 服务:
    1. 打开设置页面
    2. 选择 AI 提供商  ← 问题在这里
    3. 输入 API Key..."
4. 用户点击侧边栏"设置"，打开 SettingsPage
5. 看到5个标签: 外观、TTS、ASR、打字、学习、关于
6. 用户困惑: **没有 AI 配置标签** 😱
7. 用户尝试在各个标签页里找，找不到
8. 用户放弃，或联系客服 → 很差的体验
```

**用户影响**:
- 😞 100% 的新用户无法自主配置 AI 功能
- 😡 高期望后的失望导致负面评价
- 📉 AI Lab 功能使用率 = 0%
- ⏱️ 客服压力增大

**根本原因**:
1. Phase 9 实现了完整的 AI 服务层
2. 但 Settings 页面没有同步添加 AI 配置 UI
3. 引导文案指向不存在的功能

**解决方案**:
```
优先级: 🔴 P0 - 阻塞性
紧急度: ⚠️ Critical
影响范围: AI Lab 全部功能

方案A (推荐): 在 SettingsPage 添加 "AI配置" 标签页
- 提供商选择 (qwen, openai, volcengine, deepseek, ollama, custom)
- API Key 输入 (password 类型，带显示/隐藏切换)
- 端点 URL 输入 (带预设值)
- 模型名称输入 (带下拉建议)
- "测试连接" 按钮 (显示成功/失败/延迟)
- "保存配置" 按钮

方案B (临时): 在 AILabPage 内嵌配置表单
- 检测到未配置时显示内联配置表单
- 配置成功后隐藏表单，显示功能
- 优点: 一站式体验
- 缺点: 不符合设置习惯

方案C (最快): 修改引导文案
- 提供控制台配置代码示例
- 缺点: 依然是糟糕的用户体验
```

**时间估算**: 
- 方案A: 1天 (推荐)
- 方案B: 0.5天
- 方案C: 0.1天 (不推荐)

### Issue #2: 语音识别质量无法优化 - ASR高级设置缺失

**问题描述**:
用户旅程:
```
1. 用户在练习时发现 ASR 识别效果不理想
2. 想调整识别参数，打开"设置 → ASR"
3. 只看到3个选项:
   - ASR 提供者: [HTTP API | 浏览器内置 | Sherpa ONNX]
   - API 地址: [http://...]
   - 识别语言: [中文 | 英文]
4. 用户选择 "Sherpa ONNX" 想用本地模型
5. **没有模型选择器** 😞
6. 不知道用的是哪个模型
7. 无法测试识别效果
8. 被迫用HTTP API (可能有延迟/费用)
```

**对比旧框架**:
老框架提供:
- ✅ 6+ 预设 Sherpa 模型 (streaming-zipformer-zh, paraformer-zh...)
- ✅ 模型路径显示
- ✅ 模型类型选择 (sherpa-vad, sherpa-asr, custom)
- ✅ VAD 配置 (语音活动检测)
- ✅ 时间戳输出开关
- ✅ 完整的测试 UI:
  - 点击"测试ASR"开始录音
  - 录音时显示波形/计时
  - 停止后自动识别
  - 显示识别文本和用时

**用户影响**:
- 😞 无法使用高质量的本地 Sherpa 模型
- 🐌 依赖 HTTP API 导致延迟
- 💸 可能产生不必要的 API 费用
- 🛠️ 开发者无法调试 ASR 问题

**根本原因**:
1. 新框架只迁移了基础 UI 框架
2. 高级配置和测试功能未实现
3. 功能严重降级

**解决方案**:
```
优先级: 🔴 P0 - 功能降级
紧急度: ⚠️ High
影响范围: 语音识别质量

Phase 1: 恢复模型选择 (1天)
- 预设模型下拉框 (6+ 模型)
- 显示当前模型路径
- 模型描述和语言标签

Phase 2: 实现测试功能 (1天)
- 录音按钮 (开始/停止)
- 录音状态指示 (计时、波形)
- 识别结果显示
- 错误处理和反馈

Phase 3: 高级配置 (0.5天)
- VAD 开关和路径
- 时间戳输出
- 自定义入口脚本
```

**时间估算**: 2.5天

### Issue #3: 存储空间不可控 - 缺少数据管理

**问题描述**:
用户旅程:
```
场景1 - 长期使用:
1. 用户使用应用3个月
2. TTS 缓存累积 500+ 音频文件
3. 学习记录累积 1000+ 条
4. 占用存储空间 800MB+
5. 用户不知道，应用变慢
6. 想清理数据，找不到入口
7. 只能清除浏览器数据 → 丢失所有学习记录 😱

场景2 - 问题排查:
1. 用户遇到音频播放问题
2. 客服建议"清除 TTS 缓存"
3. 用户在设置里找不到
4. 客服只能指导清除浏览器数据
5. 课程和进度全丢失 → 用户流失
```

**对比旧框架**:
老框架提供:
- ✅ 存储统计显示 (Storage 标签)
  - TTS 缓存: 523 条，156MB
  - 学习记录: 1,234 条
  - 课程数据: 45 个课程
  - 总占用: 312MB
- ✅ 分级清理按钮:
  - "清除 TTS 缓存" - 只删除音频
  - "清除学习历史" - 删除记录和成就
  - "清除所有数据" - 需二次确认
- ✅ 清理后显示释放空间

**用户影响**:
- 😞 无法查看应用占用多少空间
- 🐌 长期使用后可能性能下降
- 😱 问题排查时被迫清除全部数据
- 📉 导致用户流失

**业务影响**:
- 客服工单增加
- 用户留存率下降
- 负面评价可能提及"占用空间大"

**解决方案**:
```
优先级: 🔴 P1 - 长期运维
紧急度: ⚠️ Medium (但影响深远)
影响范围: 所有长期用户

Phase 1: 存储统计 (0.5天)
- 新增 Storage Management 标签页
- 统计 TTS 缓存 (Dexie ttsCache 表)
- 统计学习记录 (reviewLogs, aiTaskLogs)
- 统计课程数据
- 显示总占用空间 (需 Electron API 或估算)

Phase 2: 清理功能 (0.5天)
- "清除 TTS 缓存" 按钮
  - 清除 IndexedDB ttsCache 表
  - 调用 Electron clearAudioCache API (如有)
  - 显示释放空间
- "清除学习历史" 按钮
  - 清除 reviewLogs, aiTaskLogs, achievements
  - 确认对话框
- "清除所有数据" 按钮
  - 清除所有 IndexedDB 表
  - 清除 localStorage
  - 红色警告 + 二次确认
```

**时间估算**: 1天

### Issue #4: 测试按钮是"假的" - 用户被误导

**问题**:
- 设置页面的 "测试 TTS" 和 "测试 ASR" 按钮
- 代码中是 `// TODO: 调用 API 测试`
- 点击后显示 "测试成功" (ElMessage.success)
- 实际没有发起任何请求
- 用户以为配置正确，实际可能有错

**影响**:
- 用户无法验证配置是否正确
- 遇到问题时不知道是配置错误还是其他问题
- 降低了配置的可信度

**解决方案**:
```javascript
// TTS 测试实现
async function testTTS() {
  try {
    const testText = settings.language === 'zh' ? '这是一个测试' : 'This is a test';
    await ttsApiService.speak({
      text: testText,
      provider: settings.ttsProvider,
      endpoint: settings.ttsHttpEndpoint,
      voice: settings.ttsVoice,
      speed: settings.ttsSpeed,
      volume: settings.ttsVolume
    });
    ElMessage.success('TTS 测试成功，你应该听到了测试语音');
  } catch (error) {
    ElMessage.error(`TTS 测试失败: ${error.message}`);
  }
}

// ASR 测试实现
async function testASR() {
  try {
    // 1. 请求麦克风权限
    await navigator.mediaDevices.getUserMedia({ audio: true });
    
    // 2. 显示录音对话框
    ElMessageBox.alert('点击确定开始录音，录音 3 秒后自动识别', '测试 ASR', {
      confirmButtonText: '开始录音',
      type: 'info'
    });
    
    // 3. 录音逻辑...
    // 4. 调用 ASR API
    // 5. 显示识别结果
  } catch (error) {
    ElMessage.error(`ASR 测试失败: ${error.message}`);
  }
}
```

**时间估算**: 0.5天

```javascript
class UserFriendlyError {

        title: 'API Key 无效',
        message: 'API Key 验证失败，可能已过期或输入错误',
        action: '更新 API Key',
        actionHandler: () => router.push('/settings?tab=ai')

    // 显示友好的错误对话框

  }
}
```

**预期效果**:
