# 课程数据结构一致性分析报告

## 1. 数据结构定义位置

所有主课程系统的数据结构定义集中在 `src/models/course.ts` 文件中，包含以下核心接口：

- `WordEntry`: 单词条目
- `Sentence`: 句子结构
- `AudioMeta`: 音频元数据
- `SegmentItem`: 音频片段
- `Lesson`: 课时结构
- `Course`: 课程结构

这些接口定义了完整的课程数据模型，所有课程生成方式（包括补救课程）都应使用这些定义。

## 2. 统一后的课程数据结构

### 2.1 统一数据结构设计

所有课程生成方式（包括音频导入、AI生成、PEP导入和补救课程）现在都使用统一的 `Course` 和 `Lesson` 接口定义，消除了数据结构不一致的问题。

### 2.2 统一课程构建工厂

创建了 `src/services/courseFactory.ts` 文件，提供了统一的课程构建函数：

- `buildCourse`: 构建符合规范的 `Course` 对象
- `buildLesson`: 构建符合规范的 `Lesson` 对象
- `buildSentence`: 构建符合规范的 `Sentence` 对象
- `buildWordEntry`: 构建符合规范的 `WordEntry` 对象
- `buildAudioMeta`: 构建符合规范的 `AudioMeta` 对象
- `fingerprintCourse`: 生成课程指纹，用于检测重复课程
- `mergeLessons`: 合并课时

这些工厂函数确保所有生成的课程和课时对象都具有一致的结构和必填字段。

### 2.3 音频文件存储方案

音频文件现在按以下结构存储在 `data` 目录中：

```
data/
└── audio/
    └── {courseId}/
        └── {lessonId}/
            ├── {fileName}
            └── ...
```

这种存储结构确保音频文件与课程和课时数据紧密关联，便于通过数据结构查找对应的音频文件。

## 3. 数据结构一致性分析

### 3.1 统一后的一致性

**改进**：
- 所有课程生成方式（包括补救课程）都使用相同的 `Course` 和 `Lesson` 接口定义
- 通过统一的工厂函数确保所有课程对象结构一致
- 所有课时对象都包含必填的 `modesEnabled` 和 `fields` 字段
- 移除了冗余的 `createdAt`、`updatedAt` 和 `stats` 字段，由数据库自动处理

**一致性**：
- 所有课程生成方式都使用统一的构建函数，确保生成的对象结构完全一致
- 音频课程、AI生成课程、PEP导入课程和补救课程现在都可以在同一个课程列表中展示和使用
- 减少了系统复杂度，只需要维护一套课程系统

### 3.2 补救课程系统整合

**改进**：
- 补救课程服务现在生成符合主课程系统 `Course` 和 `Lesson` 接口的课程
- 可以直接在主课程列表中展示和使用补救课程
- 简化了系统架构，不再需要维护两套独立的课程系统

## 5. 数据一致性问题与解决方案

### 5.1 已解决的问题

1. **可选字段填充不一致**：通过统一的工厂函数确保所有课程对象的可选字段填充一致
2. **补救课程结构不兼容**：将补救课程系统整合到主课程系统中，使用相同的数据结构
3. **缺少统一的课程构建机制**：创建了 `courseFactory.ts` 提供统一的课程构建函数

### 5.2 实施的解决方案

1. **统一课程构建函数**：
   - 创建了 `src/services/courseFactory.ts`，提供统一的课程构建函数
   - 所有课程生成方式都使用这些函数构建课程对象
   - 确保所有可选字段都有合理的默认值

2. **标准化可选字段填充**：
   - 工厂函数明确规定了不同课程类型应填充的可选字段
   - 所有生成方式都遵循相同的字段填充规则

3. **补救课程结构整合**：
   - 修改 `remedialCourseService.ts`，使其生成符合主课程系统 `Course` 和 `Lesson` 接口的课程
   - 修改 `remedialScheduler.ts`，使用主课程结构
   - 补救课程现在可以直接在主课程列表中展示和使用

4. **音频文件存储方案**：
   - 音频文件按课程ID和课时ID的层级结构存储
   - 确保音频文件与课程和课时数据紧密关联
   - 便于通过数据结构查找对应的音频文件
