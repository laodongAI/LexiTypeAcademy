# 学习内容与学习方法兼容性设计（v1）

- 日期：2026-10-24
- 状态：实现中，自动化验证待执行
- 范围：现有课堂入口、课堂导航和内容形态与方法的适配
- 不在本次范围：新增音素/音标独立课堂、自动将文章拆成词汇课、改造既有课程数据结构

## 1. 目标

让系统根据课时的真实内容形态和已有数据，推荐适合的学习方式；入口弹窗、课堂导航和直接 URL 访问必须执行同一套规则。对不适用的方法说明原因，避免仅因“有英文文本”就认为任何学习方法都可直接套用。

## 2. 内容形态与方法规则

| 内容形态 | 默认推荐 | 可用方法 | 不适用/前置条件 |
|---|---|---|---|
| 单词 word | 词燃尽 | 词燃尽；有明确词根/词根组数据时可用词根课堂 | 精读和句子燃尽不直接适用；词根课堂不能只靠词性分组冒充词根分组 |
| 短语 phrase | 词燃尽 | 词燃尽 | 精读、句子燃尽不直接适用；词根课堂需要明确词根数据 |
| 句子 sentence | 句子燃尽 | 有完整多词句子时可用句子燃尽；精读可查看语境 | 词燃尽需先提取目标词并形成独立词汇课；词根课堂需明确词根数据 |
| 篇章 passage | 精读 | 精读 | 句子燃尽需先拆分为独立句子；词燃尽需先提取目标词并形成独立词汇课；当前版本不自动转换 |
| 对话 dialog | 精读/整体理解 | 精读 | 句子燃尽需先拆分为独立句子；词燃尽需要先提取目标词；独立角色扮演模式不在本次实现范围 |

以上规则是当前课堂能力的兼容性闸门，不代表完整的英语教研方法目录。内容字段中存在 phonetic 音标只说明词条有发音信息，不代表系统已具备音素辨析、最小对立体或发音部位教学能力。

## 3. 统一规则实现

规则集中于 frontend/src/shared/utils/learningMethodCompatibility.ts，提供：
- isLearningMethodAvailable(lesson, mode)：检查内容形态和数据前置条件。
- getLearningMethodUnavailableReason(lesson, mode)：返回面向用户的原因。
- recommendLearningMethod(lesson)：根据内容形态和可用性选择默认方法。
- learningMethodRules：方法元数据与兼容性声明。

课堂入口弹窗和课堂页共享该注册表。直接访问带有不适用 mode 的 URL 时，课堂页回退到推荐方法并修正路由；用户点击不适用的导航项时会收到原因提示。

## 4. 验收标准

1. 单词/短语课默认词燃尽，不默认精读。
2. 句子课默认句子燃尽；没有完整多词句子时不能进入句子燃尽。
3. 篇章/对话默认精读；没有独立词汇课时不能直接进入词燃尽。
4. 没有明确词根或词根组数据时，词根课堂不可选，并解释原因。
5. 入口弹窗、课堂导航、直接 URL 访问的兼容性判断一致。
6. 不修改历史课程内容、不自动拆分或重分类课程。
7. TypeScript 检查与生产构建通过；浏览器场景需另行实测并记录证据。

## 5. 后续阶段

- P1：提供“从篇章提取目标词/句子并生成学习副本”的显式转换流程，保留来源课时与定位关系。

- P2：对话角色扮演与听说任务独立定义，不把普通精读等同于口语训练。
