# AI 课程生成、课程仓库与学习体验专项审计

> 日期：2026-10-24。静态代码审查与产品建议；未执行的本地运行测试不会标记为通过。

## 1. 总体结论与优先级

当前三种生成入口覆盖中文需求、真实音频和出版社教材，但整体仍偏向“生成一批课程数据”，还没有统一保证“内容类型—教学方法—课程层级—学习证据”完整闭环。建议先修正确性和可恢复性，再扩展生成方式。

- P0：学习恢复、任务持久化、后端故障态与日志诊断要有运行验证。
- P0：生成结果必须根据内容形态匹配教学方式，不能把单词清单默认当作精读材料。
- P1：课程仓库统一使用集合/系列、课程、课时、内容项的层级，不让批量生成的小课平铺。
- P1：三种生成方式共享生成配置、预览、质量检查、层级归属和保存流程。
- P2：根据 CEFR、学习目标、学习时间和掌握度个性化编排课程。

## 2. 三种现有生成方式

### 2.1 中文生成英文课程

入口为 AI 工具页的中文生成 tab，对应 CourseGeneratorPanel.vue。当前表单要求课程名称、中文内容、预期课程数和每节内容数；调用时难度固定为 intermediate，标签固定包含 AI、Chinese，用户不能指定 CEFR、学习目标或学习模式。预览主要展示课时标题与英文词汇标签。

关键实现风险：aiCourseDraft.ts 的 courseDraftFromGenerationResponse 将每个生成课时的内容统一映射为 ContentShape.Word。也就是说，即使输入是一段完整场景，生成结果仍可能被建模成词汇课。生成后的“立即学习”还跳到通用练习中心，而不是刚生成的课程。

本轮已实现第一阶段的真实目标选择：主题词汇与常用表达/搭配，并在预览中明确当前边界。不能把 Phrase 选项误解为完整句型、对话或短文生成。下一阶段再分别实现句型、情景对话、短文精读和综合单元的专用输出结构与质量闸门。生成结果保留词性、音标、搭配、自然例句、句型槽位、上下文和对应练习。预览需显示内容形态、预计时长、目标和学习活动；保存后直达课程详情或第一课。

### 2.2 语音导入生成课程

AudioImportPanel.vue 适合播客、视频、对话或录音等真实材料。正确流程应为：音频检查 → ASR 转写 → 用户校对 → 句子/话轮分段并保留时间戳 → 识别难度与语言点 → 选择学习目标 → 生成课程活动 → 预览保存。

不要把所有转写内容一律抽成单词。听力课应保留原音频区间、字幕和说话人；支持先听不看文本、逐句循环、降速、跟读、复述和理解题。转写失败或生成中断时，已完成的转写与用户修改应保留，不能整条流程丢失。

### 2.3 出版社教材系列

TextbookImportPanel.vue 已提供出版社、系列、教材、单元、内容类型与批量生成的流程。它的层级选择只是生成时的来源导航，不自动保证课程仓库也有同样的持久化父子关系。

批量生成多个单元时，应默认保存到同一教材系列/册的父集合中，而不是产生多个无关的同级课程。单词、句子、短文、语法和 phonics 必须使用不同的内容结构和教学模板；需验证它们是否在生成和草稿转换中保留了真实的内容形态。教材来源不明确时，不应声称是官方原版内容。

### 2.4 本轮追加的代码修正

- 中文、音频、教材课程生成/保存流程均接入诊断日志，方便定位失败发生在识别、生成还是保存阶段。
- 中文生成和音频导入的“立即学习”不再跳到泛化练习中心，而是打开刚保存的课程详情；教材批量生成打开首个已保存课程。
- 教材批量保存现在逐个记录已成功保存的课程 ID；部分保存失败后重试会跳过已成功项，降低重复创建风险。
- 音频导入预览明确说明当前生成结果主要是词汇练习，分段字幕/时间戳尚未完整进入课堂，避免用户误以为已经支持逐句音频学习。
- 课程仓库新增“层级视图”，默认按 `Collection:` 标签将中文生成和音频课程归入集合，再列出课程与课时数量；旧课程进入“未归类课程”，教材课程保留独立的教材分级视图。课程集合名通过课程现有 tags 字段持久化，暂不需要数据库迁移。

本轮已补充主题词汇/表达搭配目标选择，并将目标传递到单次生成与分批生成提示词，草稿按 Word/Phrase 保存。最新 main 的构建验证仍需等待；AI 生成语义质量和本地端到端行为尚未实测。

## 3. 还可增加的生成方式

不建议每一种输入都发展成独立的孤立页面。建议采用统一课程构建器，各类输入作为来源适配器：

| 方式 | 输入 | 适合生成的内容 |
|---|---|---|
| 目标/场景生成 | 英语面试、旅行、工作沟通等目标 | 目标拆解、主题单元、情景任务与复习计划 |
| 主题词汇 | 主题、水平、数量 | 词族、搭配、例句、主动回忆和间隔复习 |
| 真实材料 | 音频、字幕、文章、网页摘录 | 分段、难度、词句讲解、理解题与跟读 |
| 教材/考试大纲 | 教材目录、考试范围 | 系列、单元、覆盖度与知识点映射 |
| 薄弱项生成 | 错词、低准确率句型、对话反馈 | 针对性微单元、对比练习、延迟复测 |
| 词表导入 | CSV、Anki 或已有词表 | 去重、分组、补充音标/例句和分级 |
| 会话生成 | AI 教学、面试或角色扮演记录 | 高频错误、表达升级、复练卡与迁移任务 |
| 混合生成 | 目标 + 文本 + 音频 | 词汇、句型、听说读写组合课程 |

## 4. 内容类型与学习方法匹配

单词清单不适合默认把精读（intensive reading）当作主要方法。精读主要用于有完整语境的句子、对话和短文；单词更适合发音/词形识别、意义和搭配、主动回忆、语境应用与间隔复习。

| 内容类型 | 推荐学习方法 | 典型闭环 |
|---|---|---|
| 单词 | 词汇习得 + 主动回忆 | 听音辨词、词义回忆、词性/搭配、短例句、延迟复习 |
| 短语/搭配 | 块状语言学习 | 听辨、搭配选择、替换槽位、情景造句 |
| 句子/句型 | 句子精学与模仿输出 | 先听后看、意群切分、结构观察、跟读、替换、脱稿复述 |
| 对话 | 情景听说与角色扮演 | 先听整体、理解话轮、重点表达、角色替换、无提示复述 |
| 短文/文章 | 泛读后精读 | 首读主旨、二读细节、关键语言点、推断、摘要/讨论 |
| 语法 | 归纳、对比与产出 | 观察例句、归纳规则、最小对比、纠错、自由造句 |
| 发音/phonics | 听辨、示范和跟读 | 音素对比、分解模仿、录音回听、迁移到新词 |
| 音频/视频 | 听力理解与影子跟读 | 无字幕首听、核对文本、片段循环、降速、跟读、复述 |

生成后的质量闸门至少检查：结构完整、重复项、英文自然度、拼写语法、翻译对应、CEFR 难度、新词密度、学习目标、练习活动、内容与方法匹配、音频状态、来源标记和可编辑性。质量检查要报告问题，而不是把 AI 生成成功等同于内容已验证。

## 5. 课程仓库层级

建议统一主结构：学习路径/主题集合 → 系列/册/单元 → 课程 → 课时 → 内容项。教材、主题、音频来源和个性化补弱是来源元数据，不应形成彼此孤立的实体体系。

当前 CourseRepositoryPage.vue 有 grid/list/textbook 三种视图；教材视图能按系列、册、单元分组，但默认卡片视图仍会平铺课程，其他课程也会集中显示在“其他课程”列表。仅凭标题字符串或标签不能可靠地建立父子关系。

当前已先用 `Collection:` 标签实现可持久化的集合分组和层级视图，作为无损过渡方案。正式方案仍建议新增 CourseCollection/CourseNode 关系：id、parentId、nodeType、title、sortOrder、sourceMetadata、createdAt、updatedAt；课程节点引用规范课程 ID。正式模型可支持层级嵌套、排序、移动/归档和集合进度，避免把标签长期当作关系数据库。

建议默认颗粒度：一个主题课程包含多个课时；词汇课通常 8–15 个核心词；句型/场景课围绕少量目标表达；一篇短文可作为一个精读课时主体。数量只是默认值，应按难度与预计时长调整，不应为每个词创建独立课程。

## 6. 学习模块操作、逻辑与展示

建议统一课堂闭环：目标和预计时间 → 输入（听/读/看）→ 整体理解 → 引导练习 → 主动回忆 → 输出迁移 → 总结与复习。不同内容类型选择不同步骤，不要求所有课都使用同一个精读模板。

- 单词：发音、词形、核心义、搭配、短例句和主动回忆；详细内容按需展开。课堂已根据内容形态自动推荐默认模式：Word/Phrase 默认“词燃尽”，Sentence 默认“句子燃尽”，Passage/Dialog 默认“精读”。用户在 URL/界面明确选定模式时优先尊重用户选择；词汇课手动切到精读时会提示更适合的练习方式。
- 句子：支持先听后看、意群分段、句型替换和跟读。
- 对话：以话轮呈现，支持角色分离、逐句播放和角色扮演。
- 短文：先整体理解，再按需查看词语/语法，避免首遍逐词翻译。
- 每页突出一个主操作；加载、保存成功、保存失败和可重试状态必须明确。
- 目录可快速跳转；退出不等于完成；完成由明确的学习动作产生。
- 进度显示当前步骤、完成证据与待复习项，不只显示装饰性百分比。
- 音频统一控制播放/暂停/重播/降速/停止，切换项目时清理旧音频。
- 高级设置收纳到折叠区域，窄屏与键盘操作可用。

## 7. 恢复学习和任务持久化验收矩阵

| 场景 | 操作 | 预期 |
|---|---|---|
| 进入课时 | 从课程中打开第 2 课时 | 课程 ID、课时 ID 与当前步骤被保存 |
| 刷新恢复 | 课时中途刷新 | 回到同一课时；若暂不支持步骤级恢复，明确只恢复到课时 |
| 返回首页 | 课堂返回首页 | 继续学习指向正确课程与课时 |
| 浏览器重启 | 关闭前后端后重新启动 | SQLite 中的课时进度与任务状态仍存在 |
| 今日任务 | 勾选任务后刷新 | 完成状态保留，统计不重复增加 |
| 保存失败 | 停止后端后尝试更新 | 明确提示失败，不假报完成，可重试 |
| 课程被删除 | 删除上次学习课程后回首页 | 提示课程不可用并提供课程仓库入口 |
| 多标签页 | 两个标签页更新同一任务 | 最终状态以服务端数据为准，避免旧值覆盖 |

当前状态：需要在实际 Windows 运行环境执行。前端类型检查/构建只能证明编译正确，不能证明 SQLite 重启恢复、任务持久化或后端关闭后的界面状态正确。

## 8. 后端故障状态规范

- 首页按课程进度、计划、复习等分区显示状态；部分接口失败时，不把缺失数据当成 0。
- 我的学习在读取失败时显示原因与重试；保留缓存数据时标记缓存时间。
- 历史与统计在数据不可用时显示“暂不可用”和原因，不把空数组渲染为零学习。
- 至少区分后端未启动/连接拒绝、请求超时、HTTP 4xx/5xx、响应格式异常、数据库/迁移错误。
- 写请求超时后应防止重复提交；后续应引入幂等键或查询确认。
- 健康检查区分 API 可连接、数据库可读写、默认 TTS 就绪、默认 ASR 就绪。

## 9. 前端诊断日志

前端已提供可从导航进入的“运行诊断”页面：按时间、级别、来源显示前端日志，支持搜索、过滤、导出 JSON、清空；最多保留 1000 条并在刷新后保留。页面自动调用 `/api/health` 显示进程级健康状态，并通过固定路径的 `/api/diagnostics/backend-logs` 读取最近最多 500 行后端日志（每行截断并对常见 API Key/Bearer 形式脱敏）。记录前端未处理异常、Promise rejection、API 连接失败/超时/HTTP 错误和请求耗时摘要。不得记录密码、API Key、完整请求正文、音频内容或完整个人输入。健康接口仅确认进程可响应，不等同于数据库、AI、TTS、ASR 全部就绪。

后端仍将日志写入 backend/logs/app.log；诊断接口只允许读取配置指定的固定日志文件，不接受任意路径，且返回行数有上限。此接口面向本机单用户部署，若未来改为网络可访问的多用户部署，需要额外鉴权与权限控制。

## 10. 建议实施顺序

1. 接入前端诊断日志并验证导航、刷新保留、筛选、导出和清空。
2. 修正中文生成结果的内容形态错配，统一三种生成方式的预览与质量检查。
3. 按内容类型实现独立的学习活动模板。
4. 增加课程集合/节点模型与兼容迁移，避免微课程平铺。
5. 增加课堂步骤保存、恢复与任务持久化的集成测试。
6. 执行后端不可用时的手工/自动化验收，记录证据。


## 本轮课程集合正式化进展

- 新增后端独立实体 `course_collections`，字段包含 `id/name/parent_id/description/sort_order/created_at/updated_at`，支持父子集合与排序。
- 新增 `course_collection_memberships` 关系表，课程归属不再依赖课程标签，且不改写原有课程结构。
- 后端提供集合列表、新建、更新、删除、课程分配/取消归属 API；拒绝删除仍含子集合或课程的集合，并防止父子循环。
- 应用启动时只对新增的两张表执行幂等建表，不重建或改写旧业务表。
- 新增旧 `Collection:` 标签迁移接口：幂等创建集合和课程归属，保留原标签；前端课程仓库加载时调用迁移，提供新建顶层/子级集合和移动课程的操作。
- 当前前端以“父级路径”平铺显示集合节点，数据模型支持任意层级；更完整的树形拖拽排序、集合重命名/删除和迁移报告仍可继续完善。
- 状态：IMPLEMENTED_UNVERIFIED；需要最新前后端 CI 和 Windows 实际数据库验证。旧课程无集合标签的保持未归类，教材课程仍使用原教材层级视图。
