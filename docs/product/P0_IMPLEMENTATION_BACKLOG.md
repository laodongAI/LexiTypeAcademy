# P0 改进实施清单与验收标准

> 关联基线：[PRODUCT_IMPROVEMENT_BASELINE.md](./PRODUCT_IMPROVEMENT_BASELINE.md)  
> 版本：V1.0 / 2026-10-24

## 目标

先修复影响产品可信度和主要学习路径的问题，再扩展新的 AI 能力。每个任务必须有独立验收证据。

## P0-01 首页内容可信度

- **问题**：首页包含中文学习文案、固定学习统计、固定课程、固定任务。
- **用户价值**：不再把演示值误认为真实个人学习数据。
- **实施要求**：
  - 删除与英语学习无关的文案和课程示例。
  - 在真实统计数据源接入前，不显示伪造的学习天数、词汇数、准确率。
  - 在任务数据模型尚未接入前，不用可勾选的静态任务伪装真实任务；展示明确的空状态与下一步入口。
  - 首页应引导用户进入课程仓库或现有学习入口。
- **验收标准**：
  - [ ] 首页无中文学习文案或虚构课程。
  - [ ] 没有真实数据时，显示诚实的空状态。
  - [ ] 所有主按钮能进入已存在的正确路由。
  - [ ] 页面在窄窗口下不发生明显溢出。
- **测试**：前端类型检查、构建；人工启动首页核对文案与跳转。

## P0-02 首页继续学习路由

- **问题**：旧逻辑跳转 `/courses?id=<id>`，与当前详情路由结构不一致。
- **实施要求**：
  - 课程详情必须使用 `/courses/:courseId`。
  - 只有在存在真实学习记录时，才展示继续学习；后续恢复课时/位置由统一学习进度服务提供。
  - 不应以课程 ID 替代课时位置恢复能力。
- **验收标准**：
  - [ ] 课程详情路由与首页入口一致。
  - [ ] 不存在对应课程时有可理解的回退路径。
  - [ ] 恢复学习位置需要有真实数据支持，不可硬编码。
- **测试**：路由单测或人工验证课程详情、旧路由兼容和无数据场景。

## P0-03 学习计划持久化与契约核验

- **审计发现**：计划页不只是静态原型。前端已有 `studyPlanRepository`，通过 HTTP 调用计划、任务、打卡和 `/dashboard` 接口；页面消费后端看板聚合的真实数据。路由注释“数据模型待实现”已过时。
- **当前风险**：本次静态审计确认了前端契约，但尚未在运行环境验证所有后端接口、SQLite 迁移和重启持久化；计划页面仍需覆盖多计划优先级、任务状态和失败态。
- **实施要求**：
  - 更新过时路由注释，避免将已存在的能力描述为未实现。
  - 核对计划/任务/打卡 API、SQLite schema 与迁移脚本。
  - 明确任务完成、跳过、补学、重新安排的持久化语义。
  - 首页只消费看板聚合数据，不复制计划进度计算规则。
- **验收标准**：
  - [ ] 创建、编辑、暂停/恢复、删除计划可持久化。
  - [ ] 自定义任务完成/取消完成与打卡历史在刷新和重启后保持一致。
  - [ ] 看板派生值与课程进度、复习数据一致。
  - [ ] 无计划、无任务、接口失败均有独立状态。
- **测试**：创建/编辑/重启恢复/删除/重复操作及后端不可用验证。

## P0-04 TTS 无声端到端诊断

- **问题**：静态代码不足以确定无声根因。
- **实施要求**：
  - 依次观测模型可用、合成成功、音频文件有效、URL 可访问、前端取得音频、浏览器播放成功。
  - 健康检查的 `modelReady` 必须反映配置的默认引擎及其必要依赖；同时返回默认引擎可用性和不可用原因，避免“其他引擎可用”掩盖默认引擎缺失。
  - 诊断结果区分模型不可用、合成失败、URL/HTTP 错误、音频解码错误、播放被浏览器拒绝、播放被取消。
  - 统一音频调度应防止重复播放、旧音频残留和取消后状态不复位。
  - URL 播放失败时，只有在响应中存在有效音频数据时才尝试 Blob 兜底。
- **验收标准**：
  - [ ] 默认引擎的健康状态独立于其他引擎可用状态。
  - [ ] WAV 响应文件头和可解码性经过验证。
  - [ ] 音频 URL 返回预期状态码与 MIME。
  - [ ] 用户点击播放后可看到明确状态；失败有可操作提示。
  - [ ] 快速切换句子、连续点击、停止播放、卸载页面均不会留下卡住的播放状态。
- **测试**：后端 TTS 单测/接口测试；前端服务测试；Windows 实机播放验证。未在实机验证前不得标记 VERIFIED。

## P0-05 真实学习进度和事件来源

- **问题**：各页面已有真实持久化来源，但恢复位置、统计口径、读取失败状态和完成事件语义尚未统一。
- **本批实施**：
  - 新增 `learningDashboardService` 聚合学习列表、课程进度、今日练习、复习统计和计划看板。
  - 首页展示真实的继续学习、今日学习、计划任务与复习建议。
  - 进入课堂时立即持久化当前课时；学习数据读取失败不再伪装成空列表或零统计。
  - 修正学习时长字段的单位注释，口径以分钟为准，但历史导入数据仍待核对。
  - 将历史页假统计/随机日历/硬编码记录替换为真实持久化练习、复习、打字与课堂记录；累计练习时长仅统计练习记录。
  - 统计页和我的学习页在读取失败时展示错误/重试，不把默认零值冒充真实统计。
  - 详细审计见 [学习数据审计与核心学习闭环](./LEARNING_DATA_AUDIT_AND_CORE_LOOP.md)。
- **验收标准**：
  - [ ] 首页、我的学习、课程详情、统计页对同一课程的进度一致。
  - [ ] 刷新/重启后当前课时与关键状态保持一致。
  - [ ] 任务未完成、跳过、失败与成功有明确区别。
  - [ ] 统计不重复计算课堂点评、练习与计划时长。
- **测试**：同一课程跨页面更新、刷新、重启、后端故障和重复事件验证。

## P0-06 共享对话内核（后续阶段）

- **范围**：完成统一学习数据闭环后，再抽取 AI 教学、英语面试共用的会话模型、上下文构建、Provider 适配、持久化、取消/重试和评估管线。
- **设计基线**：[AI 教学与英语面试共享对话内核设计](./AI_TUTOR_AND_INTERVIEW_CONVERSATION_ARCHITECTURE.md)。
- **当前状态**：共享会话服务与 `/conversation` 页面第一版已在 main；AI 教学/英语面试复用同一会话模型，待构建、刷新恢复与实机验收。
- **验收原则**：两个场景共享基础会话内核，场景策略隔离；学习事件只在明确活动完成时写入；AI 评价提供证据与局限性。

## 建议实施顺序

1. P0-01 首页内容可信度（代码已提交、前端 CI 通过，待浏览器验收）。
2. P0-02 路由正确性与无数据状态（部分实现，待验证课时恢复）。
3. P0-03 学习计划持久化与契约核验（前端能力已存在，待后端集成验证）。
4. P0-05 首页真实数据与恢复学习闭环（前端 CI 通过，待 API 故障态与 Windows 实机验证）。
5. P0-04 TTS 端到端诊断（需实际运行环境）。
6. 统一学习事件契约与统计口径，随后进入 P0-06 共享对话内核。
