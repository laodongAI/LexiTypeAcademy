# LexiTypeAcademy 竞品亮点借鉴与第一版产品改进设计

> 状态：产品设计与实施基线；不代表建议已全部实现或通过真实课堂验收。竞品资料以公开官方页面为主，功能存在不等于学习效果已由本项目独立验证。
>

## 1. 决策摘要

### 1.1 产品目标

把 LexiTypeAcademy 从“有课程、练习、复习、语音和 AI 工具的学习应用”，持续改进为：

**学习者只需选择目标或点击继续，系统就能基于现有教材、水平和学习证据安排合适的学习活动；学习结束后留下可追溯的反馈、薄弱项和下一步任务。**

目标不是增加菜单、学习模式或 AI 开关，而是减少学员决策负担，提高学习闭环的可理解性、连续性和可信度。

### 1.2 当前项目基线与事实边界

根据 main 分支现有项目文档，当前系统已有 Vue 3 + TypeScript + Vite 前端、FastAPI 后端、本地单用户部署；课程/课时、学习进度、练习、复习、学习计划、统计相关服务/API；SQLite 业务数据主线；课程生成与课程仓库；精读、句子燃尽、词燃尽、词根、跟读、模仿、听写、翻译、复习、快速练习等路径；本地 TTS/ASR、AI 后端代理和 AI 老师课堂；学习事件、课程上下文、结构化教学输出及部分共享会话能力。

这些是可复用基础，不代表所有流程已通过真实 Windows/浏览器验收。当前仍需审计：端到端音频/录音体验、语音评分可信边界、会话反馈到学习事件的完整性、跨模块数据一致性、刷新/重启恢复、课程内容来源关系。不得假设已有完整自适应教学引擎、音素级评分或统一掌握度证据模型。

### 1.3 第一版范围

1. 首页“下一步学习”编排：继续上次学习、今日计划和待复习统一排序，但不混淆计划与实际学习历史。
2. 统一课堂体验：按内容形态选择流程，突出一个当前任务和一个主按钮。
3. 学习活动模板：单词、短语、句子、对话、文章、听力、写作、口语和面试有清晰步骤与完成证据。
4. 反馈到行动：错误/薄弱项能转成复练或复习建议，不只留下分数或聊天记录。
5. 后端教学规则与设置：默认自动决策；学员只在需要时调整目标、难度、时间和声音等少数选项。
6. 真实状态和恢复：加载、音频、录音、识别、AI、保存、部分失败和重试状态清楚，不生成假进度或假评分。

第一版暂不建设排行榜/社交竞赛、复杂徽章经济、账户体系、考试认证、第二套聊天引擎、平行学习数据层或未经验证的大规模课程库。

## 4. 产品交互：学员看到简单流程

### 4.1 全局导航职责

- **首页**：今天做什么、继续上次学习。
- **我的学习**：实际学过什么、课程进度、历史和恢复入口。
- **目标与计划**：想达到什么目标、何时学、今日任务排期。
- **课程仓库**：教材/主题/来源材料与课程组织。
- **课堂**：当前学习对象和当前活动。
- **练习与复习**：巩固已学内容、复练薄弱项。
- **AI 老师/对话**：解释、自由对话、角色扮演、英语面试；共享会话核心。
- **统计**：展示有真实数据支持的进展与证据。

学习计划回答“准备学什么/何时学”；我的学习回答“实际学了什么/学到哪里”。两者不可合并成重复的进度总览。

### 4.2 首页：一个主任务，不是一面功能墙

首屏顺序：
1. 轻量问候与今日目标（仅在真实数据可得时显示）。
2. **唯一主卡片**：继续上次学习；若无未完成学习，显示“开始今日学习”。
3. 次级提示：待复习数量、计划完成情况，并标明真实数据口径。
4. 次级入口：听说练习、AI 老师/情景对话、课程仓库。
5. 下方再显示最近学习、薄弱项和趋势。

推荐排序由统一服务执行：
1. 可恢复且未完成的课堂；
2. 已到期且适合快速完成的复习；
3. 今日计划的下一项；
4. 根据目标推荐的短练习；
5. 无数据时引导设目标或导入材料。

推荐服务必须给出推荐原因，对失效课程/已删除课时安全回退。后端故障和真实空数据必须分开。前端不得在多个页面复制一套推荐算法。

### 4.3 统一课堂：一屏只教一个当前重点

桌面布局：
- 顶部：课程/课时名称、当前活动进度、退出/保存状态。
- 中央：当前学习材料（词、句子、对话、文章或口语问题），作为视觉主焦点。
- 辅助区：提示、反馈或 AI 老师；默认轻量，可折叠。
- 底部固定操作：一个主按钮（如“听一遍”“开始练习”“提交回答”“继续”），最多一个次按钮。
- 目录仅在需要跳转时出现；窄屏自动折叠。

学员不应看到内容类型识别器、策略路由、提示词模板、模型参数或复习算法。复杂选项放入高级设置，并提供合理默认值和恢复默认入口。

### 4.4 内容类型对应的教学流程

| 内容类型 | 学员可见流程 | 后台选择逻辑 | 完成证据 |
|---|---|---|---|
| 单词 | 听/看 → 回忆意思 → 拼写/选择 → 放进例句 → 复习 | 新词优先音形义和主动回忆；识别正确但拼写错则转拼写练习 | 回忆、拼写、语境使用及延迟复习结果 |
| 短语/搭配 | 听示范 → 看语境 → 选择搭配 → 替换槽位造句 | 按搭配类型选择辨识、填空或造句 | 能在新句子中使用，而非只认得词 |
| 句子/句型 | 先听 → 按需看文本 → 分意群 → 跟读 → 替换表达 → 无提示复述 | 听力困难时先给局部提示；跟读失败先核对录音/转写状态 | 听懂、跟读尝试、句型迁移或复述 |
| 对话 | 先听整体 → 看话轮 → 重点表达 → 角色扮演 → 复盘 | 按角色和话轮组织；以词汇、提示密度、追问深度控制难度 | 目标意图完成、关键表达使用、会话复盘 |
| 短文/文章 | 首读/首听抓主旨 → 细节理解 → 重点语言点 → 摘要/复述 | 先整体后局部；避免一开始逐词翻译 | 主旨/细节理解、摘要或复述表现 |
| 听力 | 首听不显示全文 → 理解主旨/细节 → 按需看文本 → 片段循环 → 跟读/复述 | 保留原始音频来源；有时间戳才按片段播放，不伪造同步 | 理解题、片段辨识、复述或跟读尝试 |
| 写作/打字 | 读题 → 自己写 → 看关键反馈 → 自己修订 → 对比前后稿 | 优先反馈最影响理解/目标的 1–3 项，按水平控制解释 | 原稿、修订稿、修改差异和迁移任务 |
| 口语 | 看问题 → 可选提示 → 录音/说话 → 回听/转写 → 反馈 → 再说一次 | 提示逐级增加；先确认录音/ASR 有效，再评估语言表现 | 录音状态、转写、语言反馈、重试结果 |
| 英语面试 | 选目标/岗位（可选）→ 回答 → 适度追问 → 复盘 → 重练 | 会话核心负责消息与恢复；面试策略负责题目、追问、回答结构 | 原始回答、结构建议、例证缺口、下一轮练习 |

### 4.5 一分钟口语任务

入口只显示“练习口语 1 分钟”，不把评分维度或内部模型暴露在开始页。

1. 显示清晰问题和预计时长；可选“给我一点提示”。
2. 提示阶梯：关键词 → 句子开头 → 示例思路；示范不是标准答案。
3. 录音前说明麦克风用途；明确录音中、停止、识别中、分析中状态。
4. 完成后先显示“你表达了什么”（转写/录音回放），再显示 1–3 个最有价值的改进。
5. 只有服务支持且证据充分时才显示评分；区分语言表现推断和真实发音评估。
6. 主按钮“再练一次”；次按钮“保存重点表达”。保存项应保留来源并可进入复习。

异常流程：
- 麦克风未授权：说明如何授权，提供文字回答替代路径。
- 录音为空/过短：不评分，提示重新录制。
- ASR 失败：显示“暂时无法识别”，保留录音供回听/重试，不给低分。
- AI 失败：保留原始回答与转写；重试不重复创建用户消息。
- 刷新/离开：按真实持久化能力恢复；不支持恢复录音时必须明确，不能假称完整恢复。

### 4.6 写作修订流程

- 原稿提交后保留，不被 AI 覆盖。
- 反馈聚焦关键问题，按“问题 → 为什么 → 提示/例子”组织。
- 学员自行修订；AI 可提供局部建议，默认不替换全文。
- 显示原稿与修订稿差异，明确学员做出的修改。
- 复测使用新题或新语境，避免只记住被改写的句子。
- 不确定时说明不确定，不编造 CEFR 分数或权威考试等级。

### 4.7 AI 对话和场景角色扮演

复用项目已有对话核心；场景配置只决定教学策略，不复制消息存储、流式请求、重试或历史记录。

| 场景 | 目标 | 对话中策略 | 结束时产物 |
|---|---|---|---|
| AI 老师 | 理解课程重点、解决疑问、完成练习 | 读取当前课程/内容和相关学习证据；按需解释、提问和提示 | 本次重点、完成步骤、待练点、下一步 |
| 自由对话 | 自然交流中练表达 | 保持角色和语境；不频繁打断；允许即时轻提示或课后反馈 | 摘要、关键纠错、自然表达、新词和复练 |
| 情景对话 | 完成真实场景目标 | 维持角色；按水平减少提示；必要时追问 | 场景目标完成情况、关键表达、重练入口 |
| 英语面试 | 练回答结构和具体例证 | 逐题提问、适度追问；反馈结构/证据/清晰度，不代替招聘判断 | 回答优点、证据缺口、改进建议、下一轮问题 |

反馈应引用学员原话或转写，区分原始输入、ASR 结果、AI 建议和系统测量。模型自评不能直接作为客观掌握度。

## 5. 后端教学编排与配置

### 5.1 建议服务职责

优先扩展现有服务，不创建平行系统。

- **学习任务聚合/推荐服务**：汇总可恢复课堂、计划任务、到期复习和薄弱项，返回一个推荐动作及原因。
- **教学编排服务（候选）**：依据目标、内容形态、水平、近期表现和可用能力，选择活动模板与下一步。
- **规则注册表/配置**：保存规则 ID、优先级、条件、动作、适用范围、默认值、版本和回退策略。
- **学习证据服务（渐进建设）**：统一记录练习、复述/写作修订、对话反馈、复习结果和证据可信度。
- **现有课程/复习/语音/对话服务**：继续作为能力提供方，不在前端复制业务规则。

后端输出“下一项活动 + 当前材料 + 主操作 + 可选提示 + 失败回退 + 证据要求”；前端按统一 UI 契约渲染，不自行猜测教学顺序。

### 5.2 规则决策顺序

1. 安全与数据完整性：服务不可用、数据不完整或来源不明确时，不生成虚假结果。
2. 用户显式目标：当前明确选择优先于自动推荐，除非能力不可用。
3. 学习对象与内容形态：单词、句子、对话、文章不能套用同一模板。
4. 学习证据：优先处理反复错误、到期复习和未完成任务。
5. 难度与提示量：从低门槛开始，依据成功/失败证据调整。
6. 时间与偏好：短时目标缩小任务量，但不能降低证据真实性。
7. AI 候选建议：AI 可生成反馈或下一活动候选；确定性规则校验，持久化服务负责最终状态。

### 5.3 第一版规则表

| 规则 ID | 触发条件 | 系统动作 | 学员看到的内容 | 禁止行为 |
|---|---|---|---|---|
| RULE-NEXT-001 | 存在可恢复未完成课堂 | 推荐恢复课堂 | “继续上次学习” | 不跳转到无关课程，不丢失当前课时 |
| RULE-NEXT-002 | 无可恢复课堂，有到期复习 | 推荐短复习 | “复习几个学过的词”或真实数量 | 不把接口失败显示为“没有待复习” |
| RULE-NEXT-003 | 无课堂/复习，有今日计划 | 推荐计划下一项 | 任务名与真实预计时间 | 不复制计划进度算法 |
| RULE-CONTENT-001 | 内容类型为单词/短语 | 选择词汇/搭配模板 | 当前词与简单操作 | 不默认套用文章精读 |
| RULE-CONTENT-002 | 内容类型为文章/对话 | 先整体理解，再局部讲解 | “先听/读一遍” | 不强迫首屏展示全部语言点 |
| RULE-HELP-001 | 首次失败或轻微错误 | 给局部提示 | “看一个提示” | 不立即展示完整答案 |
| RULE-HELP-002 | 同类错误重复出现 | 给简短解释和对比例句 | “看看区别，再试一次” | 不重复无效提示 |
| RULE-SPEECH-001 | ASR 失败/录音无效 | 保留录音并允许重试 | “暂时无法识别，可以重试” | 不把 ASR 失败当作发音差 |
| RULE-SPEECH-002 | 无可靠评分证据 | 隐藏分数并说明原因 | “本次暂时无法评估” | 不返回固定默认分 |
| RULE-WRITE-001 | 学员提交写作 | 保存不可变原稿，返回可执行反馈 | 重点问题、解释、修改入口 | 不覆盖原稿 |
| RULE-REVIEW-001 | 复习失败 | 生成不同形式的短复练并保留证据 | “再练一次这个表达” | 不只重复原题 |
| RULE-CONV-001 | 场景对话结束 | 汇总纠错/词汇并提供复练 | 重点反馈和“再练一次” | 不未经验证把 AI 建议写成掌握记录 |

### 5.4 规则配置示例（契约草案）

    rule_id: RULE-CONTENT-001
    version: 1
    enabled: true
    priority: 100
    when:
      content_types: [word, phrase]
      activity_state: start
    then:
      activity_template: vocabulary_recall
      primary_action: start_practice
    fallback:
      activity_template: simple_review
      learner_message: "先完成一个简短练习"
    explain_to_learner: false
    telemetry_event: teaching_rule_applied

规则要求：
- 稳定 ID、版本、启停状态、优先级和适用范围。
- 决策输入来自明确字段，不能依赖页面标题或字符串猜测父子关系。
- 冲突有确定性处理顺序；记录命中规则和回退原因，日志不得泄露 API Key、完整录音或不必要的个人输入。
- 学员可见解释使用白话文案，不直接显示内部规则 ID。
- 配置缺失或无匹配规则时走安全默认流程，不随机选择活动。
- 规则变更后执行固定回归样例，比较活动选择、失败回退和可见输出。
- AI 输出是候选；只有契约校验通过且满足证据要求，才可进入学习记录或复习状态。

### 5.5 设置页：少量常用项，高级项折叠

默认可见：
- 每次学习时长：短（约 5 分钟）/标准（约 10–15 分钟）/较长（约 20 分钟）。
- 学习目标：系统提升、听说、词汇句型、工作/面试（可选）。
- 英语语音：默认音色/试听；语速正常或稍慢。
- 反馈方式：简洁提示（默认）/详细解释。

高级设置折叠：
- CEFR 级别（可选，不强迫初学者选择）。
- 自动显示文本、提示强度、练习顺序偏好。
- TTS/ASR 诊断、模型/provider 状态、缓存和隐私选项。
- 显示真实支持范围；不可用项禁用并解释原因。“恢复默认”只影响设置，不清除学习历史。

## 6. 数据契约与可信度

### 6.1 不新增重复数据源

课程、课时、课程进度、计划、复习、练习记录继续使用现有仓储/API 和 SQLite 主线；新增事件前先检查统一学习事件契约，定义幂等语义和统计口径。TTS Blob 是可重建缓存，不是业务学习记录。若写作版本、对话反馈或学习证据现有模型不支持，先做字段/表影响分析和迁移设计，不用 localStorage 或标签代替永久业务关系。

### 6.2 学习证据类型

- **活动完成**：用户确实完成指定动作。
- **回答结果**：原始输入、提交时间、练习结果。
- **语言反馈**：AI 或规则建议，记录来源和置信边界。
- **语音结果**：录音是否成功、ASR 是否成功、转写、可用评分维度和来源。
- **掌握度**：只有满足既定复习/评估规则的证据才更新；单次答对或 AI 自述不代表长期掌握。
- **来源关系**：词/句/反馈可追溯到课程、课时、原文、音频片段或会话；生成副本不能覆盖原材料。

### 6.3 隐私

本项目本地优先，但外部 AI Provider 仍可能接收文本、音频或个人资料。应说明传输范围和用途，最小化保存语音与面试回答；清理、迁移、重试不能静默覆盖数据。

## 7. 视觉与交互规范

### 7.1 信息层级

- 每页一个明确首要目标和一个主按钮。
- 主材料优先，辅助解释按需展开；历史记录默认折叠或降权。
- 页面标题说明“正在做什么”，按钮说明“点击后发生什么”。
- 课程进度、活动进度、正确率和掌握度不能混为一个数字。
- 桌面和窄屏保留主操作；键盘焦点、标签和可访问名称清楚。

### 7.2 统一状态词汇

| 内部状态 | 学员文案示例 | 交互要求 |
|---|---|---|
| idle | 准备好了 | 主按钮可用 |
| loading | 正在准备学习内容… | 防重复提交；可取消时提供取消 |
| playing | 正在播放 | 暂停/停止清楚 |
| recording | 正在录音 | 计时、停止和麦克风状态可见 |
| transcribing | 正在识别你的回答… | 防重复提交 |
| evaluating | 正在整理反馈… | 保留输入并说明状态 |
| saved | 已保存 | 只在持久化成功后确认 |
| partial_success | 部分内容已完成 | 列明成功/失败项和恢复方式 |
| retryable_error | 暂时没成功，可以重试 | 保留输入/录音；重试不重复创建记录 |
| unavailable | 当前无法使用这项功能 | 提供可行替代方式 |
| unassessable | 本次暂时无法评估 | 不显示伪造分数 |

### 7.3 音频规则

同一课堂路径同一时刻只允许一个主要播放任务；切句、切课时、退出、取消时清理旧音频/任务。区分 TTS 合成失败、URL/解码失败、浏览器拒绝播放和用户主动停止。自动播放被阻止时提供“点击播放”。TTS/ASR 不可用时，阅读和文本练习仍可用。波形、评分和播放进度必须来自真实数据。

## 8. 第一版实施路线与依赖

### 阶段 0：证据与可信度门禁（P0）

1. 以当前 main 重新核对首页、课堂、跟读/模仿、复习、AI 老师和课程仓库。
2. 对照现有 P0 清单，处理仍未验证的音频、评分、状态、学习位置恢复和跨模块一致性；避免重复修复已解决项。
3. 区分代码审查、自动化、真实运行和用户效果四类证据。
4. 明确哪些功能只恢复到课时、哪些恢复到活动步骤，不夸大恢复能力。

### 阶段 1：最小学习路径编排（P0/P1）

1. 在现有服务上聚合“继续学习、待复习、今日计划”。
2. 返回一个主推荐动作及可解释原因；后端故障与空数据分开。
3. 首页只消费聚合结果，不复制计划/复习算法。
4. 单元测试覆盖无数据、多候选、失效课程、接口失败、优先级冲突和幂等。

### 阶段 2：课堂活动模板统一（P1）

1. 把现有方法映射到内容类型、活动步骤、主按钮、完成证据和回退路径。
2. 先选择单词、句子、文章/对话、跟读四条代表路径，优先复用现有组件。
3. 不同时重写所有方法；每完成一类就补自动化和浏览器验收。
4. 统一音频控制、进度语义、退出/恢复与失败状态。

### 阶段 3：反馈到复练（P1）

1. 先支持口语反馈、写作修订、AI 对话复盘的结构化呈现。
2. 数据契约和来源关系明确后，再把纠错/词汇转成复习项。
3. 为 AI 输出建立 schema 校验、置信边界和失败回退。
4. AI 不直接写掌握度；通过确定性服务验证后产生学习事件。

### 阶段 4：轻量自适应（P2）

1. 基于重复错误、延迟复习和新情境迁移逐步调整活动。
2. 先用可解释的确定性规则并记录推荐原因和结果。
3. 建立真实学习样本基线后，再决定是否需要更复杂模型/规则框架。
4. 不先建设排行榜、复杂积分、自动生成无限课程或完整学习画像。

## 9. 验收标准

### 9.1 产品体验
- [ ] 新用户打开首页后无需读说明即可知道如何开始。
- [ ] 有未完成课堂时，主操作优先恢复正确课程/课时。
- [ ] 无未完成课堂时，按真实复习/计划数据推荐下一项；无数据时显示诚实空状态。
- [ ] 每种学习活动主按钮清晰，学员无需理解内部方法名称。
- [ ] 内容类型不同，流程确实不同；不把所有内容塞进精读模板。
- [ ] 失败后保留输入/录音/草稿（适用时），重试不重复创建消息或记录。
- [ ] 计划、我的学习、课堂、复习和统计职责与数据口径一致。

### 9.2 教学质量
- [ ] 单词/短语练习包含回忆或语境使用，不只是展示词条。
- [ ] 文章/对话支持整体理解后再局部讲解。
- [ ] 写作反馈保留原稿，让学员自行修订。
- [ ] 口语提示按需展开，示范答案不是唯一标准。
- [ ] 对话结束后有可执行反馈和下一步，不只给总分。
- [ ] 复练使用不同形式或新语境，避免只重复原题。
- [ ] 每个分数、进度和掌握度均有数据来源与定义。

### 9.3 工程与 UI
- [ ] 不创建平行课程、计划、复习或会话数据源。
- [ ] 推荐服务区分空数据、部分成功和读取失败。
- [ ] 规则冲突、无匹配规则和依赖不可用时有确定性回退。
- [ ] 音频、录音、ASR、AI、保存和重试状态符合 UI/UX 规范。
- [ ] 桌面、窄屏、键盘焦点和暗色主题有验收记录。
- [ ] 单测、类型检查、构建、后端测试记录真实结果。
- [ ] Windows/真实浏览器 E2E 与用户效果分别记录；未执行项为 NOT_RUN。
- [ ] 设计、任务状态、交接记录与实现一致。

## 10. 风险与待核实事项

1. 现有课堂方法与内容类型映射须按当前 main 代码复核，不能只按文档推断。
2. 共享对话核心已有部分实现，但场景策略、持久化、反馈到学习事件的完整性仍需审计。
3. 语音评分边界必须严格保留；文本相似度不是音素级发音评分。
4. 课程来源、教材版权、音频时间戳和生成副本关系必须可追溯。
5. 数据不足时给明确的默认下一步，不展示伪精确个性化解释。
6. 不设未经基线测量的学习效果提升百分比；先建立开始耗时、完成率、恢复成功率、错误复现率等基线。
