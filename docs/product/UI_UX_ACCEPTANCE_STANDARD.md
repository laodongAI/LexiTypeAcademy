# LexiType Academy UI/UX 交互验收规范

> 版本：V1.0 / 2026-10-24  
> 适用范围：所有新增或修改的页面、弹窗、表单、课堂、音频与录音交互。

## 1. 用户体验目标

用户应始终知道：当前在哪里、能做什么、系统正在做什么、操作结果是什么、失败后如何恢复。

## 2. 页面状态规范

每个涉及异步数据的页面必须定义以下状态：

- **初始/加载中**：提供可见反馈；防止用户误以为无响应。
- **成功/有数据**：展示真实数据及明确的主操作。
- **空状态**：说明为空的原因（若已知），提供下一步操作。
- **失败状态**：用用户可理解的语言说明失败类别，保留可恢复输入，提供重试。
- **保存中**：阻止重复提交并显示进度状态。
- **保存成功**：给出明确确认，避免依赖短暂且容易错过的提示。
- **部分成功**：明确成功与失败部分，不得伪装为全部成功。
- **无权限/能力不可用**：说明原因和可选替代方式。

## 3. 按钮与操作

- 主按钮只对应当前场景的首要行动。
- 按钮文字应描述动作，例如“开始学习”“保存计划”，避免含义模糊的“确定”。
- 异步操作期间防止重复提交。
- 禁用按钮应有可理解原因；不应只靠灰色表达。
- 危险操作必须明确影响范围；不可逆操作需要二次确认。
- 取消操作不得悄悄保存或丢弃用户数据。
- 成功提示必须与真实结果一致。
- 所有交互控件必须有键盘焦点态、合理的可访问名称和可操作区域。

## 4. 学习进度与数据

- 不得以静态示例数据冒充用户真实学习记录。
- 课程进度、任务完成和复习状态必须来自持久化数据或明确标记的演示模式。
- 单次正确率不能直接作为长期掌握度。
- 课程完成、练习完成、跳过和中断必须区分。
- 任何数据迁移、清理、导入或恢复操作都应说明影响范围，并在可行时提供备份/回滚。

## 5. 音频播放规范

每个播放控件至少支持明确的状态：待播放、生成/加载中、播放中、暂停、已完成、失败、已取消。

- 连续点击不应创建重复播放。
- 播放新内容时，应按照统一规则停止或切换旧音频。
- 页面卸载、切换课时和取消任务时，应清理播放器与调度状态。
- 播放失败需区分合成失败、网络/URL 失败、解码失败和浏览器拒绝播放（若可检测）。
- URL 播放失败时，不能无限静默重试；若存在有效音频 Blob，可进行一次受控兜底。
- 语速调整应说明适用范围，并提供恢复默认。
- 语音选择应展示真实支持语言和试听结果。

## 6. 录音与 ASR

- 明确录音前准备、权限用途与麦克风状态。
- 录音开始、录音中、识别中、评分中、完成和失败状态必须可见。
- 权限被拒绝或设备不可用时，提供恢复说明。
- 用户应能回听自己的录音；重录不能无提示覆盖已有结果。
- ASR 失败不能直接等同于发音差。
- 置信度不足时，评分应标记为不确定或无法评估，而非给出看似精确的分数。

## 7. AI 交互

- 区分生成中、成功、超时、限流、网络失败和模型不可用。
- 支持取消或重试时，应保证消息状态一致，不重复发送已成功请求。
- 对 AI 反馈区分事实、建议和不确定判断。
- 教学反馈要指出具体问题、解释原因并给出可执行练习。
- 示范答案应适配用户水平，不应默认追求复杂表达。
- 上传简历、录音和声音样本前，明确数据用途、发送范围、保存方式与删除方式。

## 8. 表单与编辑

- 必填项与字段级校验错误清晰可见。
- 校验失败保留用户输入。
- 离开未保存页面时提示保存、继续编辑或放弃。
- 重名、冲突和重复提交要有确定的处理策略。
- 高级设置默认简洁展示，并可查看说明、恢复默认。
- 删除声音档案、学习历史或缓存时，应明确选择范围。

## 9. UI 一致性与可访问性

- 复用项目已有组件与设计 token，不要在页面中随意新增颜色、间距和按钮样式。
- 浅色/暗色主题下都要检查文字与控件对比度。
- 不仅使用颜色表达错误、成功或选择状态。
- 支持键盘操作、可见焦点、语义化标题和表单标签。
- 页面在常见桌面尺寸和窄窗口下不应出现关键内容溢出。
- 响应式布局不能把主要操作藏在难以发现的位置。

## 10. 每个 PR 的 UI/UX 验收清单

- [ ] 主任务与主按钮清晰。
- [ ] 加载、空、成功、失败状态完整。
- [ ] 重复点击和异步状态处理正确。
- [ ] 用户输入不会因失败或导航意外丢失。
- [ ] 文案、统计与实际功能一致。
- [ ] 键盘焦点与可访问名称可用。
- [ ] 暗色主题和窄窗口已检查或说明未验证。
- [ ] 重要用户路径有自动化测试或可复现的人工验证步骤。
- [ ] 未运行的测试没有被标记为通过。
