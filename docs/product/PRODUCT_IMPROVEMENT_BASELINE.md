# LexiType Academy 产品改进基线

> 版本：V1.0  
> 建立日期：2026-10-24  
> 范围：产品体验、学习流程、AI 教学、语音能力、数据可信度、UI/UX 与工程验收  
> 基线原则：区分代码已证实事实、待运行验证项与产品增强建议，不把推测写成已确认缺陷。

## 1. 产品定位

LexiType Academy 是面向个人学习者的本地优先 AI 英语学习应用。目标不是堆叠孤立的工具，而是帮助用户持续完成“明确目标—开始学习—理解输入—练习输出—获得反馈—安排复习—验证掌握”的闭环。

### 1.1 首要用户群

1. **系统提升型成年人**：需要词汇、句子、基础听力和口语的渐进式学习，希望打开应用后马上知道今天学什么。
2. **听说强化型学习者**：需要真实语音、重复播放、跟读、录音回听、可理解的发音反馈。
3. **目标驱动型学习者**：例如准备英语面试、工作沟通或日常场景表达，需要场景化训练和复盘。

第一阶段不以覆盖所有学习人群为目标，优先服务以上三类用户的共同需求：低启动成本、连续学习、可恢复、反馈可信。

## 2. 产品体验原则

1. **首页先回答“下一步做什么”**：继续学习或今日学习应成为视觉主行动，其他工具作为次级入口。
2. **学习状态可信**：统计、任务、课程进度和掌握度必须来自真实数据；演示数据必须明确标记。
3. **学习过程可恢复**：保存课程、课时、句子/单词位置和必要的练习状态；刷新或意外退出后可继续。
4. **功能围绕学习闭环组织**：课程、课堂、练习、复习、计划和统计共享统一的数据语义。
5. **错误可以理解和恢复**：播放、录音、AI 请求、保存或迁移失败必须有状态说明、重试或替代路径。
6. **默认简单、高级可选**：初学者可使用合理默认值，高级用户可调模型、音色、语速和练习方式。
7. **AI 反馈必须说明证据边界**：不能把 ASR 文本相似度包装成音素级发音准确率，也不能把一次答对等同于长期掌握。
8. **隐私透明**：明确哪些数据本地保存，哪些音频、文本或个人资料会发送到外部服务。
9. **交互一致**：按钮、加载、空状态、错误提示、危险操作和键盘行为遵守统一规范。
10. **可验证交付**：每个开发任务必须有验收标准、测试证据和未完成事项；未执行的测试不得标为通过。

### 3.2 待运行验证（不要在未验证前宣称为已确认缺陷）

- TTS 无声的实际根因：模型加载、生成响应、音频 URL、Blob 兜底、浏览器播放权限、音频调度等各层都需要验证。
- 首页、课程详情和课堂在真实运行时的路由跳转与导航高亮。
- 课程、练习、复习与统计是否已在其他服务中存在可复用的统一数据来源。
- 播放队列在快速切换课时、取消请求、连续点击和页面卸载时是否正确清理。
- 录音权限被拒绝、设备不可用、ASR 超时和评分失败时的恢复行为。
- 小窗口、暗色主题、键盘导航、屏幕阅读器与高对比度表现。
- 旧数据迁移的重复执行、失败回滚、数据冲突和备份恢复。

### 3.3 产品增强建议

- 首页根据真实学习状态生成今日建议，并提供 5/10/20 分钟等轻量入口。
- 课堂统一组织听、看、说、练、反馈与复习。
- 建立基于多次学习证据的掌握度，而非单次正确率。
- 建设可复用的 AI 对话/教学模块，支持面试、日常对话和课程内辅导。
- 对 TTS 模型按自然度、语言覆盖、情感、克隆能力、延迟、资源占用和授权进行基准评测。

## 4. 信息架构基线

| 导航域 | 用户任务 | 核心入口 |
|---|---|---|
| 学习首页 | 确定下一步 | 继续学习、今日任务、待复习 |
| 学习课程 | 选择与持续学习 | 课程仓库、我的学习、学习计划 |
| 练习提升 | 强化能力 | 词汇、句子、打字、听力、口语 |
| 场景实战 | 迁移到真实使用 | 英语面试、日常对话、角色扮演 |
| 学习进步 | 了解变化 | 学习记录、薄弱项、阶段复盘 |
| 设置 | 配置与数据管理 | TTS/ASR、AI 服务、隐私、备份、外观 |

以上是目标架构，不意味着当前所有模块都已经实现。导航中未完成的功能应标注状态或暂不作为主路径推广。

## 5. 核心用户旅程

### 旅程 A：首次使用
打开应用 → 了解产品能做什么 → 选择学习目标/水平（允许跳过）→ 推荐一项短任务 → 进入课堂 → 完成第一次练习 → 看到明确反馈 → 保存进度。

验收重点：首次启动不要求配置大量模型参数；模型不可用时说明限制，并允许浏览课程或使用可用功能。

### 旅程 B：日常继续学习
打开首页 → 一键继续上次内容 → 听/看/说/练 → 自动保存位置 → 完成本节 → 查看总结和待复习内容 → 结束。

验收重点：恢复到真实位置；刷新/关闭后状态可恢复；没有真实数据时不显示虚构统计。

### 旅程 C：听力与口语
选择句子 → 试听 → 调整语速/显示文本 → 录音跟读 → 回听自己的录音 → 查看有证据支撑的反馈 → 重试或加入专项练习。

验收重点：播放与录音状态明确；失败原因可区分；ASR 置信不足时不得直接给出强结论。

### 旅程 D：英语面试
选择岗位/难度 → 模拟对话 → 选择提示强度 → 回答并接受追问 → 查看表达反馈 → 将薄弱项转为练习 → 再次模拟验证。

验收重点：反馈以可执行改进为主，不把示范答案写成用户必须背诵的唯一答案。

## 6. 优先级定义

- **P0：正确性与信任**。错误路由、虚构数据、数据丢失风险、核心学习流程不可用、语音无声等。
- **P1：核心学习体验**。课堂闭环、恢复学习、统一音频控制、复习联动、可靠反馈。
- **P2：个性化与增强能力**。新模型、情感语音、更多场景、长期能力画像和高级分析。

## 7. 产品指标

先建立基线，再设置目标，不凭空设定通过阈值。

- 操作：首次开始学习耗时、继续学习成功率、关键任务完成率、误操作率、错误恢复率。
- 学习：延迟回忆、重复错误率、听力理解、无提示表达完成率。
- 语音：TTS 生成成功率、实际播放成功率、首音频延迟、ASR 失败率、评分与人工判断一致性。
- 可靠性：学习位置恢复成功率、迁移成功率、备份恢复成功率。
- 信任：虚构/错误进度事件数应为 0；关键失败必须有可理解反馈。

## 8. 交付规则

每个任务必须包含：背景、用户影响、目标范围、非目标、验收标准、受影响模块、测试命令/验证步骤、风险与回滚方式。

状态仅可标记为：
- `TODO`：尚未开始。
- `IN_PROGRESS`：正在实施。
- `IMPLEMENTED_UNVERIFIED`：代码已改但尚未完成验证。
- `VERIFIED`：有可追溯的测试或人工验证证据。
- `BLOCKED`：被明确依赖或环境问题阻塞。

不能因代码已提交就将任务标记为 VERIFIED。
